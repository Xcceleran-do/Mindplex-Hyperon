# Production Ingestion Path

The ingestion code separates source access, planning, extraction, and
conversion.

## Token-use controls

Set `INGESTION_ENABLED=false` to reject new ingestion through the API and have
the frontend open the existing dataset directly. This is enforced by the
backend as well as hidden in the built frontend.

Successful Mindplex ingestion writes freshness metadata beside `data.metta`.
Requests for the same username and an equal or smaller article limit reuse that
dataset for three days without calling Mindplex or the extraction model. Change
the window with `INGESTION_CACHE_TTL_DAYS`; `0` disables caching. An intentional
refresh can send `{"username": "author", "force": true}` to `/api/ingest`.
The provided Compose deployment stores both the generated dataset and this
metadata in the persistent `ingestion-data` volume, so container recreation does
not itself trigger another paid ingestion. Remove that volume only when the
cached dataset should also be discarded.

1. `pipeline.run_ingestion(...)` fetches raw records from a source.
2. `ExtractionPlanner` samples the records and creates an `ExtractionPlan`.
   If `ASI_API_KEY` is present, this plan is generated by the LLM. If
   `INGESTION_PLAN_JSON` is set, that pinned plan is used instead. By default
   production ingestion requires the LLM; set `INGESTION_REQUIRE_LLM=false` only
   for local fallback testing.
3. `IngestionOrchestrator` delegates properties to specialized agents:
   `structured_field`, `numeric_bucket`, `date_bucket`, and `text_llm`.
4. `JsonToMetta` converts every extracted property generically, so MeTTa output
   is no longer tied to a fixed article-property list.

Mindplex is one source implementation. A generic JSON API source should normally
be configured server-side with `INGESTION_SOURCE_URL` and
`INGESTION_RECORDS_PATH`. For development only, set
`INGESTION_ALLOW_REQUEST_URLS=true` to allow `/api/ingest` to receive a URL:

```json
{
  "source": "custom-json",
  "limit": 50,
  "source_config": {
    "url": "https://example.com/items.json",
    "records_path": "data.items"
  }
}
```

For production deployments, validate the LLM-created plan once and then pin it
with `INGESTION_PLAN_JSON`. That keeps extraction deterministic while preserving
automated schema discovery.

The generated MeTTa facts intentionally exclude identity/display predicates by
default: `author`, `authored-by`, `author-username`, and `title`. Override
`INGESTION_EXCLUDED_PREDICATES` only if a deployment explicitly wants those
fields in the miner input.
